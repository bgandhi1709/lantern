# The agents run in a Node.js service with a read-only identity, called with a run id

Plan, Ask and Check agents run in `lantern-agents`, a Node.js + TypeScript (strict) app in its own Container App in the existing environment, with internal ingress only. It calls the Anthropic API directly through the official TypeScript SDK's Tool Runner, with Claude Haiku 4.5 and the Chapter as a cached prefix. `Lantern.Api` and `Lantern.Functions` remain the only writers.

A caller authenticates with its managed identity (an Entra token for the agent service's app registration) and passes only a run id. `Lantern.Api` writes the run (Family, Child, Chapter, kind, state, expiry) before queueing it; the agent service loads it and refuses one that is expired, finished or from another caller. Tools read their scope from the run, so the model never sees or chooses a Family or Child id, and a prompt injection in a note cannot widen it. The service's identity has read-only data roles, scoped as tightly as the storage layout allows, and read access to its own Key Vault secret (the Anthropic key). The run id is the correlation id across the API, Service Bus, Functions, the agent service and Anthropic, and tokens are logged per run.

Node.js was chosen so the founder can review the agent layer; orchestration is I/O-bound, so Python or .NET would bring no meaningful performance gain, and the Expo app shares the language. The cost is a second runtime: its own Dockerfile, Bicep, CI job, tests and coding standards, about 4.5 days, and roughly ₹550 a month of compute at ten pilot Families once the free grant is used (₹88 to the dollar, list prices).

Considered and rejected: agents inside `Lantern.Api` (the API's identity can write everything), a sidecar in the API's Container App (managed identity is per app, so isolation would be lost, and it saves no compute), a hosted MCP server (too broad), forwarding the Parent's Firebase token (all of the Parent's powers, and it expires before a queued run), a shared privileged token (one secret opens every Family), Microsoft Foundry (a direct key now exists), the Claude Agent SDK (built-in file and shell tools are attack surface a parent product doesn't need) and Managed Agents (beta, per-session containers, and the tools would have to be reachable from outside).
