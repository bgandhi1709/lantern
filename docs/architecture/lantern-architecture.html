Lantern Architecture

Parent app, API, Functions and storage are built and run in UAT; the Ask and Plan agents are planned · NCERT and SSC content comes from a separate repository · 22 Oct 2026

Content: made elsewhere

  • • Extracting the syllabus is part of the separate lantern-utilities repository (ADR-0017)
  • • Board rules run once there, not in the API (#151)
  • • Output lives in private Blob containers, never in this repo

The Parent app

  • • Google sign-in through native Firebase
  • • Registers a Family and its Children in one call
  • • Names, email, birth year and school are locked on the phone
  • • A new phone opens the Family with the emailed Recovery code
  • • Start again, in Settings, deletes the Family

API and actions

  • • Layered API: controllers, services, repositories (ADR-0005)
  • • Slow work is an action on one Service Bus queue (ADR-0004)
  • • Each Child gets a Workspace in Blob and a Content slice
  • • The Family manifest is a derived index (ADR-0014)
  • • Deleting a Family signs its Parents out at once, then erases the rest

Cost and safety

  • • Scales to zero, at most one replica per app
  • • No keys anywhere: managed identity + RBAC
  • • Lantern holds no Family key: the Parent's Recovery code is the only one
  • • Deleting a Family erases its rows and the wrapped key (DPDP Act 2023)
  • • AI is about 95% of running cost, so every model call is reused first
